M2.6 — Phân tích mối quan hệ giữa feature và target¶

Mục tiêu¶

Sau M2.4 và M2.5, các feature chính đã được hiểu tương đối rõ về distribution, cardinality, missingness và semantic đặc biệt.

M2.6 chuyển sang câu hỏi:
Target Is Fraud? thay đổi như thế nào giữa các nhóm giá trị của feature?

Các nhóm feature được khảo sát gồm:

  • Amount;
  • Use Chip;
  • MCC;
  • các feature dẫn xuất từ thời gian;
  • location và location missingness.

Nguyên tắc bắt buộc¶

Mỗi phân tích categorical phải xem đồng thời:
transaction_count
fraud_count
fraud_rate

Không được kết luận một category có rủi ro cao chỉ vì fraud rate cao khi support rất nhỏ.

Lift so với fraud rate toàn dataset chỉ được dùng như đại lượng mô tả tương đối, không phải bằng chứng nhân quả.

Ảnh hưởng từ các finding trước¶

M2.3 đã xác nhận target distribution thay đổi mạnh theo thời gian.

Do đó một quan hệ feature ↔ target trên toàn dataset chưa chắc ổn định qua các temporal regime.

M2.6 sẽ bổ sung một kiểm tra độ ổn định theo các giai đoạn quan trọng đã phát hiện ở M2.3.

M2.5 đã xác nhận location missing có quan hệ cấu trúc rất mạnh với transaction mode.

Do đó missing location ↔ fraud phải được xem cùng Use Chip, không được diễn giải missing như một fraud signal độc lập.

Ranh giới¶

Trong M2.6:

  • chưa lựa chọn final feature set;
  • chưa encoding;
  • chưa feature selection bằng model;
  • chưa huấn luyện classifier;
  • chưa đưa ra causal claim;
  • chưa dùng raw User, Card, Merchant Name làm candidate feature;
  • không sử dụng Errors? trong Model V1.

Mục tiêu của M2.6 là phát hiện và mô tả association, không chứng minh causation.

def parse_amount(amount_series):
    cleaned = (
        amount_series
        .astype("string")
        .str.replace(
            "$",
            "",
            regex=False,
        )
        .str.replace(
            ",",
            "",
            regex=False,
        )
        .str.strip()
    )

    return pd.to_numeric(
        cleaned,
        errors="coerce",
    )


def update_single_group(
    total_counter,
    fraud_counter,
    values,
    fraud_mask,
):
    total_counter.update(
        values
        .value_counts(
            dropna=False
        )
        .to_dict()
    )

    fraud_counter.update(
        values.loc[
            fraud_mask
        ]
        .value_counts(
            dropna=False
        )
        .to_dict()
    )


def update_multi_group(
    total_counter,
    fraud_counter,
    group_df,
    fraud_mask,
):
    total_counts = (
        group_df
        .value_counts(
            dropna=False
        )
    )

    fraud_counts = (
        group_df.loc[
            fraud_mask
        ]
        .value_counts(
            dropna=False
        )
    )

    total_counter.update(
        {
            (
                key
                if isinstance(
                    key,
                    tuple,
                )
                else (key,)
            ):
                int(value)

            for key, value
            in total_counts.items()
        }
    )

    fraud_counter.update(
        {
            (
                key
                if isinstance(
                    key,
                    tuple,
                )
                else (key,)
            ):
                int(value)

            for key, value
            in fraud_counts.items()
        }
    )

for chunk_number, chunk in enumerate(
    pd.read_csv(
        DATA_PATH,
        usecols=M26_USECOLS,
        chunksize=CHUNK_SIZE,

            TARGET_COLUMN: "string",
        },
    ),
    start=1,
):
    total_rows += len(chunk)

    # --------------------------------------------------------
    # Target
    # --------------------------------------------------------

    target = (
        chunk[TARGET_COLUMN]
        .astype("string")
        .str.strip()
    )

    target = target.mask(
        target.eq("")
    )

    missing_target_count += int(
        target.isna().sum()
    )

    fraud_mask = (
        target.eq("Yes")
        .fillna(False)
    )

    total_fraud += int(
        fraud_mask.sum()
    )

    # --------------------------------------------------------
    # Amount
    # --------------------------------------------------------

    amount_numeric = parse_amount(
        chunk["Amount"]
    )

    amount_sign = pd.Series(
        np.select(
            [
                amount_numeric < 0,
                amount_numeric == 0,
                amount_numeric > 0,
            ],
            [
                "negative",
                "zero",
                "positive",
            ],
            default="missing_or_invalid",
        ),
        index=chunk.index,
        dtype="string",
    )

    update_single_group(
        amount_sign_total,
        amount_sign_fraud,
        amount_sign,
        fraud_mask,
    )

    amount_mode_df = pd.DataFrame(

def build_relationship_df(
    total_counter,
    fraud_counter,
    feature_name,
):
    rows = []

    for value, transaction_count in (
        total_counter.items()
    ):
        fraud_count = int(
            fraud_counter.get(
                value,
                0,
            )
        )

        fraud_rate_pct = (
            fraud_count
            / transaction_count
            * 100
        )

        rows.append(
            {
                feature_name:
                    value,

                "transaction_count":
                    int(
                        transaction_count
                    ),

                "fraud_count":
                    fraud_count,

                "fraud_rate_pct":
                    fraud_rate_pct,

                "lift_vs_overall":
                    (
                        fraud_rate_pct
                        / overall_fraud_rate_pct
                    ),

                "fraud_share_pct":
                    (
                        fraud_count
                        / total_fraud
                        * 100
                    ),
            }
        )

    return pd.DataFrame(
        rows
    )


def build_multi_relationship_df(
    total_counter,
    fraud_counter,
    column_names,
):
    rows = []

    for key, transaction_count in (
        total_counter.items()
    ):
        fraud_count = int(
            fraud_counter.get(
                key,
                0,
            )
        )

        fraud_rate_pct = (
            fraud_count
            / transaction_count
            * 100
        )

        row = {
            column:
                value

            for column, value
            in zip(
                column_names,
                key,
            )
        }

        row.update(
            {
                "transaction_count":
                    int(
                        transaction_count
                    ),

                "fraud_count":
                    fraud_count,

                "fraud_rate_pct":
                    fraud_rate_pct,

                "lift_vs_overall":
                    (
                        fraud_rate_pct
                        / overall_fraud_rate_pct
                    ),

                "fraud_share_pct":
                    (
                        fraud_count
                        / total_fraud
                        * 100
                    ),
            }
        )

        rows.append(
            row
        )

    return pd.DataFrame(
        rows
    )

Nhận xét M2.6.6¶

Quan hệ giữa hour_of_day và fraud rõ hơn đáng kể so với transaction-frequency pattern đơn thuần ở M2.4.

Fraud rate thay đổi mạnh theo giờ.

03:00 ≈ 0.1865%
04:00 ≈ 0.1828%
10:00 ≈ 0.1872%
11:00 ≈ 0.1812%.

20:00 ≈ 0.0272%
21:00 ≈ 0.0205%
22:00 ≈ 0.0116%
23:00 ≈ 0.0359%.

Như vậy hour_of_day có association rõ với target trên full dataset và không chỉ phản ánh lượng transaction trong từng giờ.

Đối với day_of_week, khác biệt tồn tại nhưng yếu hơn.

Fraud rate thấp nhất nằm ở Thứ Tư ≈ 0.0838%, trong khi cao nhất ở Chủ Nhật ≈ 0.1554%.

M2.3 đã chứng minh fraud prevalence thay đổi rất mạnh giữa các temporal regime, vì vậy không được xem những pattern giờ / ngày / tháng này là ổn định theo thời gian nếu chưa có kiểm tra bổ sung.

Location representation có association rất mạnh với target.

Ở cấp semantic location status:

STATE_ZIP_PRESENT
→ 21,508,765 transaction
→ 4,905 fraud
→ fraud rate ≈ 0.0228%
→ chỉ khoảng 0.19× fraud rate toàn dataset.

CITY_ONLINE_STATE_ZIP_MISSING
→ 2,720,821 transaction
→ 18,349 fraud
→ fraud rate ≈ 0.6744%
→ lift ≈ 5.53×.

STATE_PRESENT_ZIP_MISSING
→ chỉ 157,314 transaction
→ nhưng có 6,503 fraud
→ fraud rate ≈ 4.13%
→ lift ≈ 33.88×.

Như vậy nhóm State present nhưng Zip missing chỉ chiếm một phần nhỏ dataset nhưng chứa khoảng 21.85% toàn bộ fraud.

Kết hợp finding của M2.5, nhóm này chủ yếu đại diện cho non-online / international merchant location, không đơn giản là một lỗi thiếu Zip ngẫu nhiên.

Khi stratify thêm theo transaction mode, association vẫn tồn tại rất mạnh:

Chip + STATE_PRESENT_ZIP_MISSING
→ 51,521 transaction
→ 4,243 fraud
→ fraud rate ≈ 8.24%
→ lift ≈ 67.5×.

Swipe + STATE_PRESENT_ZIP_MISSING
→ 105,793 transaction
→ 2,260 fraud
→ fraud rate ≈ 2.14%
→ lift ≈ 17.5×.

Do đó association của STATE_PRESENT_ZIP_MISSING không thể được giải thích hoàn toàn chỉ bằng Use Chip.

Một pattern khác là nhóm Chip + City=ONLINE + State/Zip missing gồm 7,601 transaction nhưng 0 fraud, trong khi Online Transaction cùng location status có fraud rate khoảng 0.676%.

Điều này tiếp tục cho thấy transaction mode và semantic location phải được xét cùng nhau.

Ở raw location category, xuất hiện nhiều association cực mạnh.

Ví dụ:
Merchant State = Italy: 8,730 transaction, fraud rate khoảng 53.63%;
Merchant State = Algeria: 654 transaction, fraud rate khoảng 96.18%;
Merchant City = Rome: 13,765 transaction, fraud rate khoảng 34.02%;
Merchant City = Algiers: 654 transaction, fraud rate khoảng 96.18%.

Một số category có fraud rate gần hoặc bằng 100%, nhưng support của nhiều category khá nhỏ.

Ví dụ Funafuti = 59 / 59 fraud; con số 100% này không được xem là bằng chứng mạnh chỉ vì rate cực đoan.

Tuy nhiên một số location như Rome/Italy có hàng nghìn transaction và hàng nghìn fraud, nên association không thể bị bỏ qua như noise support nhỏ.

Ở Zip level cũng tồn tại những fraud rate cực cao trong các Zip support thấp hoặc vừa.

Đặc biệt, <MISSING> Zip chứa 24,852 fraud, tương đương khoảng 83.5% toàn bộ fraud, nhưng M2.5 đã chứng minh Zip missing trộn nhiều semantic mechanism khác nhau.

Do đó không được diễn giải Zip missing như một causal fraud signal độc lập.

Các raw location association rất mạnh có nguy cơ hoạt động như proxy cho merchant identity hoặc logic của synthetic fraud generator.

Chúng có thể hữu ích trong artifact này nhưng cũng tạo rủi ro shortcut, high-cardinality overfitting và generalization kém nếu distribution thay đổi.

Kết luận: location chứa association cực mạnh với target, đặc biệt ở nhóm State-present/Zip-missing và một số international location. Association vẫn tồn tại sau khi stratify theo transaction mode, nhưng mức cực đoan của nhiều raw location category tạo rủi ro synthetic shortcut; chưa có cơ sở để tự động giữ toàn bộ City/State/Zip làm feature trực tiếp.

Tổng kết M2.6 — Phân tích mối quan hệ giữa feature và target¶

Các phát hiện chính¶

M2.6 xác nhận nhiều feature có association rõ với target trên toàn dataset.

Các association mạnh xuất hiện ở:

  • transaction mode;
  • upper tail của Amount;
  • một số MCC;
  • hour_of_day;
  • semantic location status;
  • một số raw location category.

Tuy nhiên M2.6 cũng xác nhận một finding quan trọng hơn:
feature-target association không ổn định theo thời gian.

Một số relationship rất mạnh trên full history suy yếu, đảo thứ tự hoặc biến mất hoàn toàn ở các giai đoạn gần cuối dataset.

Do đó không được sử dụng full-dataset fraud rate như bằng chứng duy nhất để chọn feature cho mô hình dự đoán tương lai.

Kết luận về Use Chip ↔ target¶

Trên full dataset, Online Transaction có fraud rate khoảng 0.676%, cao hơn Chip và Swipe nhiều lần và chứa khoảng 61.66% toàn bộ fraud.

Tuy nhiên relationship này không ổn định.

Trong 2018, Chip có fraud rate cao hơn Online; trong 10 tháng đầu 2019, Online không có fraud trong khi Chip tiếp tục có fraud rate khoảng 0.187%.

Vì vậy Use Chip có association với target nhưng ý nghĩa của từng category thay đổi theo temporal regime.

Use Chip vẫn là candidate feature hợp lý, nhưng phải được đánh giá bằng temporal validation thay vì dựa trên full-history statistics.

Kết luận về Amount ↔ target¶

Amount sign đơn lẻ không tạo association mạnh theo hướng negative Amount nguy hiểm hơn.

Positive Amount thậm chí có fraud rate cao hơn negative và zero khi aggregate toàn dataset.

Ngược lại, magnitude của Amount dương cho thấy association rõ ở upper tail.

Nhóm Q10 có fraud rate khoảng 0.454%, lift khoảng 3.72× và chứa khoảng 35.47% toàn bộ fraud.

Do đó information về magnitude của Amount có giá trị EDA rõ hơn sign đơn thuần.

Kết luận về Amount sign × Use Chip ↔ target¶

Interaction giữa Amount sign và transaction mode rất mạnh trên full history.

Negative + Online có fraud rate khoảng 6.64%, cao hơn mức chung khoảng 54×.

Tuy nhiên relationship này giảm còn khoảng 1.53% trong 2018 và bằng 0 trong 10 tháng đầu 2019.

Vì vậy đây là một association mạnh nhưng không ổn định theo thời gian.

Nhóm Zero + Online có fraud rate cực cao nhưng chỉ gồm 9 transaction, nên không được coi là finding đáng tin ở mức population rule.

Kết luận về MCC ↔ target¶

MCC có association rất không đồng đều với target.

Một số MCC có support lớn và fraud contribution cao, ví dụ MCC 5311 chứa hơn 4,800 fraud và khoảng 16.2% toàn bộ fraud.

Một số MCC support tương đối lớn lại không có fraud trong toàn artifact.

Một số MCC support nhỏ hơn có fraud rate rất cao.

Điều này cho thấy MCC có predictive association tiềm năng nhưng đồng thời tạo rủi ro shortcut trong synthetic dataset.

Không được lựa chọn MCC dựa trên fraud rate đơn độc; support và temporal stability phải được xem cùng nhau.

Kết luận về các feature thời gian ↔ target¶

hour_of_day thể hiện association rõ với target trên full history, với fraud rate thay đổi mạnh giữa các giờ.

day_of_week có association mức vừa, còn month có khác biệt nhỏ hơn.

Tuy nhiên các feature thời gian aggregate trên toàn bộ 30 năm có thể trộn nhiều temporal regime khác nhau.

Do đó đây là candidate feature chứ chưa phải bằng chứng về pattern ổn định trong future data.

Kết luận về location ↔ target¶

Location tạo ra một số association mạnh nhất trong toàn bộ M2.6.

Nhóm STATE_PRESENT_ZIP_MISSING có fraud rate khoảng 4.13% và chứa khoảng 21.85% toàn bộ fraud dù chỉ có khoảng 157 nghìn transaction.

Sau khi stratify theo mode, association vẫn rất mạnh: Chip trong nhóm này có fraud rate khoảng 8.24%, Swipe khoảng 2.14%.

Một số international location có fraud rate cực cao và support không hoàn toàn nhỏ.

Điều này cho thấy location có khả năng chứa tín hiệu mạnh trong synthetic artifact.

Tuy nhiên raw City/State/Zip có cardinality cao và có thể đóng vai trò proxy cho merchant identity hoặc fraud-generation mechanism.

Do đó chúng có rủi ro overfitting, memorization và synthetic shortcut cao hơn những feature transaction tổng quát.

Chưa có cơ sở để giữ toàn bộ raw location category làm direct model features chỉ từ kết quả M2.6.

Kết luận về structural missingness ↔ target¶

Location missing có association rất mạnh với fraud, nhưng M2.5 đã chứng minh missingness mang semantic structure.

State/Zip missing không phải một biến độc lập ngẫu nhiên mà gắn với Online Transaction hoặc international merchant pattern.

Do đó fraud association của missing indicator không được diễn giải là “missing gây fraud”.

Nếu missing indicator được sử dụng sau này, phải xem xét redundancy với Use Chip và Merchant City / location status.

Kết luận về độ ổn định của association theo thời gian¶

Temporal instability được xác nhận trực tiếp.

Các relationship mạnh như Online ↔ fraud và Negative + Online ↔ fraud thay đổi đáng kể giữa full history, 2018 và 2019.

Đặc biệt Online Transaction chuyển từ nhóm fraud rate rất cao trên full dataset thành nhóm fraud rate thấp ở 2018 và 0 fraud trong 10 tháng đầu 2019.

Do đó full-history association không thể được xem là proxy đáng tin cho future association.

Đây là một bằng chứng mạnh ủng hộ temporal split, temporal validation và việc xem xét training window thay vì random split.

Các relationship có dấu hiệu mạnh nhưng cần cảnh giác¶

Các relationship sau đáng chú ý nhưng không được biến trực tiếp thành rule hoặc feature-selection decision:
Online Transaction ↔ fraud
Negative + Online ↔ fraud
Amount upper tail ↔ fraud
một số MCC ↔ fraud
State-present / Zip-missing ↔ fraud
một số international City / State / Zip ↔ fraud

Lý do cần cảnh giác gồm:

  • temporal instability;
  • support không đồng đều;
  • high-cardinality category;
  • interaction giữa nhiều feature;
  • synthetic generator bias;
  • khả năng tạo shortcut hoặc proxy cho merchant identity.

M3 phải sử dụng temporal split làm evaluation chính.

Feature usefulness không nên được đánh giá bằng random split trên toàn lịch sử.

M3 cần thiết kế validation window để kiểm tra feature association và model performance trên giai đoạn tương lai.

Việc chọn training window phải cân nhắc temporal regime shift đã phát hiện ở M2.3 và M2.6.

Các metric phải phù hợp với class imbalance và không sử dụng Accuracy đơn độc.

Final test phải chứa đủ positive class; 2020 tiếp tục không phù hợp làm final fraud test.

Các vấn đề cần chuyển sang M4¶

M4 cần quyết định representation của Amount nhưng phải giữ nguyên dấu cho tới khi có quyết định có căn cứ.

Nếu dùng transformation hoặc binning Amount, mọi parameter / boundary phải được fit chỉ từ training data.

M4 cần quyết định encoding cho MCC và location với lưu ý về long-tail, high cardinality và shortcut risk.

Không nên mặc định one-hot encode toàn bộ Merchant City hoặc Zip chỉ vì chúng có fraud association mạnh.

Missing-location representation phải cân nhắc redundancy giữa Use Chip, Merchant City = ONLINE, State missing và Zip missing.

Các limitation còn mở¶

Temporal stability mới được kiểm tra trực tiếp cho Use Chip và Amount sign × Use Chip.

MCC và location có association rất mạnh nhưng chưa được audit chi tiết theo nhiều temporal window trong M2.6.

Việc kiểm tra độ ổn định của các association này nên được tiếp tục khi so sánh temporal training windows ở M2.8 / M3.

Các extreme fraud rate của raw location / MCC có thể phản ánh synthetic fraud-generation mechanism; chưa có cơ sở để xem chúng là behavior có thể generalize sang banking data thực tế.

M2.6 chỉ xác nhận association, không chứng minh causation.
