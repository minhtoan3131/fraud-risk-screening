M2.4 — Phân tích phân bố từng feature giao dịch¶

Mục tiêu¶

Sau khi M2.3 đã làm rõ target và sự thay đổi theo thời gian, M2.4 chuyển sang khảo sát từng nhóm feature của giao dịch.

Câu hỏi trung tâm của bước này là:
Một transaction điển hình trong dataset có đặc điểm như thế nào nếu chưa xét đến target?

Các nhóm feature được khảo sát gồm:

  • Amount — phân bố giá trị giao dịch;
  • Use Chip — phân bố hình thức giao dịch;
  • MCC — phân bố merchant category;
  • các biến dẫn xuất từ thời gian — hour_of_day, day_of_week, month;
  • các trường location — Merchant City, Merchant State, Zip.

Logic phân tích¶

M2.4 thực hiện EDA đơn biến.

Tức là trước tiên trả lời:
feature tự nó phân bố như thế nào?

Chưa trả lời:
feature này liên quan đến fraud như thế nào?

Quan hệ feature ↔ target được dành cho M2.6.

Ranh giới¶

Trong M2.4:

  • chưa sử dụng Is Fraud? để so sánh các nhóm feature;
  • chưa xử lý Amount âm hoặc Amount bằng 0;
  • chưa xử lý missing location;
  • chưa xóa outlier;
  • chưa encoding category;
  • chưa quyết định feature cuối cùng;
  • chưa quyết định preprocessing.

Mục tiêu của M2.4 là hiểu hình dạng và cấu trúc feature trước khi quyết định phải điều tra sâu ở đâu.

Thiết lập môi trường thực thi¶

Notebook này được thiết kế để chạy độc lập, không phụ thuộc kernel hoặc biến đã được tạo trong M2.1–M2.3.

Do dataset có hơn 24 triệu transaction, M2.4 sử dụng hai phạm vi dữ liệu:

Full scan
→ dùng cho count, frequency, min, max, mean và các bảng tổng hợp cần độ chính xác toàn dataset.

Mẫu 1% có thể tái hiện
→ chỉ dùng cho quantile xấp xỉ và trực quan hóa phân bố Amount.

Mọi output sử dụng sample phải được ghi rõ là sample, không được trình bày như population statistic chính xác.

M24_USECOLS = [
    "Year",
    "Month",
    "Day",
    "Time",
    "Amount",
    "Use Chip",
    "MCC",
    "Merchant City",
    "Merchant State",
    "Zip",

def parse_amount(amount_series):
    cleaned = (
        amount_series
        .astype("string")
        .str.replace(
            "$",
            "",
            regex=False,
        )
        .str.replace(
            ",",
            "",
            regex=False,
        )
        .str.strip()
    )

    return pd.to_numeric(
        cleaned,
        errors="coerce",
    )


# ============================================================
# Biến tổng hợp
# ============================================================

total_rows = 0
chunk_count = 0


# Amount
amount_count = 0
amount_sum = 0.0
amount_sum_of_squares = 0.0

amount_min = None
amount_max = None

amount_negative_count = 0
amount_zero_count = 0
amount_positive_count = 0

amount_sample_parts = []


# Category / temporal frequency
use_chip_counts = Counter()

mcc_counts = Counter()

hour_counts = Counter()
day_of_week_counts = Counter()
month_counts = Counter()

merchant_city_counts = Counter()
merchant_state_counts = Counter()
zip_counts = Counter()


# ============================================================
# Full scan
# ============================================================

for chunk_number, chunk in enumerate(
    pd.read_csv(
        DATA_PATH,
        usecols=M24_USECOLS,
        chunksize=CHUNK_SIZE,
    ),
    start=1,
):
    chunk_count = chunk_number
    total_rows += len(chunk)

    # --------------------------------------------------------
    # Amount
    # --------------------------------------------------------

    amount_numeric = parse_amount(
        chunk["Amount"]
    )

    valid_amount = (
        amount_numeric
        .dropna()
    )

    amount_count += len(
        valid_amount
    )

    amount_sum += float(
        valid_amount.sum()
    )

    amount_sum_of_squares += float(
        np.square(
            valid_amount.to_numpy(
                dtype="float64"
            )
        ).sum()
    )

    if not valid_amount.empty:
        chunk_min = float(
            valid_amount.min()
        )

        chunk_max = float(
            valid_amount.max()
        )

        if (
            amount_min is None
            or chunk_min < amount_min
        ):
            amount_min = chunk_min

        if (
            amount_max is None
            or chunk_max > amount_max
        ):
            amount_max = chunk_max

    amount_negative_count += int(
        (valid_amount < 0).sum()
    )

    amount_zero_count += int(
        (valid_amount == 0).sum()
    )

    amount_positive_count += int(
        (valid_amount > 0).sum()
    )

    # Mẫu 1% dùng cho quantile / visualization
    amount_sample_parts.append(
        valid_amount.sample(
            frac=AMOUNT_SAMPLE_FRAC,
            random_state=(
                RANDOM_STATE
                + chunk_number
            ),
        )
    )

    # --------------------------------------------------------
    # Use Chip
    # --------------------------------------------------------

    use_chip_counts.update(
        chunk["Use Chip"]
        .dropna()
        .value_counts()
        .to_dict()
    )

    # --------------------------------------------------------
    # MCC
    # --------------------------------------------------------

    mcc_counts.update(
        chunk["MCC"]
        .dropna()
        .value_counts()
        .to_dict()
    )

    # --------------------------------------------------------
    # Hour of day
    # --------------------------------------------------------

    hour = pd.to_numeric(
        chunk["Time"]
        .astype("string")
        .str.slice(0, 2),
        errors="coerce",
    )

    hour_counts.update(
        hour
        .dropna()
        .astype(int)
        .value_counts()
        .to_dict()
    )

    # --------------------------------------------------------
    # Day of week
    # --------------------------------------------------------

    transaction_date = pd.to_datetime(
        {
            "year":
                chunk["Year"],

            "month":
                chunk["Month"],

            "day":
                chunk["Day"],
        },
        errors="coerce",
    )

    day_of_week = (
        transaction_date
        .dt.dayofweek
    )

    day_of_week_counts.update(
        day_of_week
        .dropna()
        .astype(int)
        .value_counts()
        .to_dict()
    )

    # --------------------------------------------------------
    # Month
    # --------------------------------------------------------

    month_counts.update(
        chunk["Month"]
        .dropna()
        .value_counts()
        .to_dict()
    )

    # --------------------------------------------------------
    # Location
    # --------------------------------------------------------

    merchant_city_counts.update(
        chunk["Merchant City"]
        .dropna()
        .value_counts()
        .to_dict()
    )

    merchant_state_counts.update(
        chunk["Merchant State"]
        .dropna()
        .value_counts()
        .to_dict()
    )

    zip_counts.update(
        chunk["Zip"]
        .dropna()
        .value_counts()
        .to_dict()
    )

    # --------------------------------------------------------
    # Progress
    # --------------------------------------------------------

    if (
        chunk_number % 10 == 0
        or len(chunk) < CHUNK_SIZE
    ):
        print(
            f"Đã xử lý {chunk_number} chunk "
            f"- tổng số dòng: {total_rows:,}"
        )


# ============================================================
# Ghép sample Amount
# ============================================================

amount_sample = pd.concat(
    amount_sample_parts,
    ignore_index=True,
)


print("\nHoàn tất quét M2.4.")
print("Số chunk:", chunk_count)
print(
    "Tổng số dòng:",
    f"{total_rows:,}",
)

print(
    "Số Amount trong sample:",
    f"{len(amount_sample):,}",
)

M2.4.2 — Phân bố Amount¶

Vì sao kiểm tra này tồn tại?¶

Amount là feature numerical trực tiếp quan trọng nhất của transaction.

Đối với một biến số, bước đầu tiên cần hiểu:

  • mức trung tâm;
  • độ phân tán;
  • khoảng giá trị;
  • độ lệch của distribution;
  • phần đuôi có dài hay không;
  • có nhóm giá trị đặc biệt cần điều tra riêng hay không.

Câu hỏi¶

Amount điển hình nằm ở khoảng nào?

Mean và median có cách xa nhau không?

Phân bố có bị lệch mạnh hay có đuôi dài không?

Min / max cách xa phần lớn transaction đến mức nào?

Phương pháp¶

Các thống kê sau được tính chính xác từ full scan:

  • count;
  • min;
  • max;
  • mean;
  • standard deviation;
  • số Amount âm / bằng 0 / dương.

M2.4.3 — Phân bố hình thức giao dịch Use Chip¶

Vì sao kiểm tra này tồn tại?¶

Use Chip là feature categorical có ba category rõ nghĩa nghiệp vụ.

Với categorical feature, câu hỏi đầu tiên không phải mean hay median mà là:
mỗi category xuất hiện bao nhiêu và có category nào chi phối dataset hay không?

M2.4.4 — Phân bố Merchant Category Code¶

Vì sao kiểm tra này tồn tại?¶

MCC được lưu dưới dạng số nhưng về ý nghĩa là categorical code.

Do đó không tính mean hoặc standard deviation của MCC như một numerical feature.

Câu hỏi phù hợp là về frequency và độ tập trung của category.

Câu hỏi¶

Có bao nhiêu MCC thực tế?

Transaction có tập trung vào một số ít MCC hay phân bố tương đối đều?

Có xuất hiện cấu trúc long-tail — một số MCC rất phổ biến và nhiều MCC ít gặp — hay không?

Phương pháp¶

Từ full scan, tạo bảng:
MCC → transaction_count → transaction_share_pct → cumulative_share_pct

Đồng thời xác định số MCC tối thiểu cần để bao phủ lần lượt 50%, 80%, 90% và 95% toàn bộ transaction.

def categories_needed_for_share(
    frequency_df,
    target_share_pct,
):
    mask = (
        frequency_df[
            "cumulative_share_pct"
        ]
        >= target_share_pct
    )

    if not mask.any():
        return len(frequency_df)

    return int(
        mask.idxmax()
        + 1

def add_frequency_share(
    frequency_df,
):
    result = (
        frequency_df
        .copy()
    )

    total_non_missing = (
        result[
            "transaction_count"
        ].sum()
    )

    result[
        "share_of_non_missing_pct"
    ] = (
        result[
            "transaction_count"
        ]
        / total_non_missing
        * 100
    )

    result[
        "cumulative_share_of_non_missing_pct"
    ] = (
        result[
            "share_of_non_missing_pct"
        ]
        .cumsum()
    )

    return result

merchant_city_df = (

        merchant_city_df

    add_frequency_share(
        merchant_state_df

def categories_needed_for_non_missing_share(
    frequency_df,
    target_share_pct,
):
    mask = (
        frequency_df[
            "cumulative_share_of_non_missing_pct"
        ]
        >= target_share_pct
    )

    if not mask.any():
        return len(frequency_df)

    return int(
        mask.idxmax()
        + 1
    )

Tổng kết M2.4 — Phân tích phân bố từng feature giao dịch¶

Các phát hiện chính¶

M2.4 đã hoàn thành EDA đơn biến cho các nhóm feature chính gồm Amount, Use Chip, MCC, thời gian và location.

Các feature có cấu trúc rất khác nhau: Amount là biến số có distribution lệch và tail dài; Use Chip là categorical feature ba nhóm với mức support không cân bằng; MCC có cấu trúc tập trung kết hợp long-tail; thời gian có pattern trong ngày rõ; location có cardinality từ vừa đến rất cao.

Không phát hiện bất nhất giữa các thống kê cấu trúc của M2.4 và Milestone 1.

Kết luận về Amount¶

Amount có phân bố không đối xứng, mean cao hơn median và có phần đuôi dương dài.

Phần lớn transaction nằm ở vùng Amount tương đối thấp, trong khi một số giao dịch có giá trị lớn hơn rất nhiều so với phần lớn dataset.

Dataset đồng thời chứa khoảng 5.10% Amount âm và khoảng 0.083% Amount bằng 0.

Các giá trị này chưa được coi là lỗi và chưa bị thay đổi.

Amount âm / zero / extreme values được chuyển sang M2.5 để điều tra sâu hơn.

Kết luận về Use Chip¶

Swipe Transaction là hình thức phổ biến nhất với khoảng 63.09%.

Chip Transaction chiếm khoảng 25.78%.

Online Transaction chiếm khoảng 11.13% nhưng vẫn có hơn 2.7 triệu transaction.

Do đó cả ba category đều có support đủ lớn để tiếp tục phân tích.

Mối quan hệ giữa Use Chip và missing location được chuyển sang M2.5; quan hệ giữa Use Chip và fraud được chuyển sang M2.6.

Kết luận về MCC¶

Dataset có 109 MCC, nhưng transaction tập trung mạnh vào một số category phổ biến.

Chỉ 6 MCC đã bao phủ ít nhất 50% transaction, 15 MCC bao phủ ít nhất 80%, 23 MCC bao phủ ít nhất 90% và 34 MCC bao phủ ít nhất 95%.

MCC vì vậy thể hiện cấu trúc concentration + long-tail rõ rệt.

Khi phân tích MCC ↔ fraud ở M2.6, cần luôn xem transaction_count cùng fraud rate để tránh diễn giải quá mức các MCC có support thấp.

Kết luận về các biến thời gian¶

Transaction có pattern theo giờ trong ngày rất rõ.

Hoạt động thấp trong khoảng nửa đêm đến sáng sớm, tăng mạnh từ khoảng 06:00, cao trong phần lớn ban ngày và giảm dần về tối.

hour_of_day vì thế là một candidate feature có cơ sở từ distribution thực tế.

Ngược lại, transaction frequency theo thứ trong tuần gần như đồng đều.

Frequency theo tháng cũng tương đối đều và chưa cho bằng chứng đủ mạnh về seasonality nếu chỉ nhìn raw transaction count.

Quan hệ giữa các biến thời gian và fraud sẽ được kiểm tra ở M2.6.

Kết luận về location¶

Location có cardinality không đồng nhất: Merchant State thấp hơn đáng kể so với Merchant City và Zip.

City và đặc biệt Zip có cardinality cao, vì vậy encoding trực tiếp có thể tạo representation lớn và cần được M4 cân nhắc dựa trên bằng chứng từ các bước EDA tiếp theo.

Một finding quan trọng là Merchant City = ONLINE xuất hiện hơn 2.7 triệu lần.

Giá trị này không phù hợp với cách hiểu đơn giản rằng Merchant City luôn là một thành phố địa lý, nên phải được điều tra cùng transaction mode và missing State/Zip ở M2.5.

Các vấn đề cần chuyển sang M2.5¶

M2.5 cần điều tra ý nghĩa và pattern của Amount âm, Amount bằng 0 và các Amount cực trị trước khi quyết định có cần xử lý hay không.

M2.5 cần kiểm tra cấu trúc missing của Merchant State và Zip, đặc biệt trong quan hệ với Use Chip = Online Transaction và Merchant City = ONLINE.

M2.5 cũng tiếp tục kiểm tra các exact duplicate đã được phát hiện ở M1 thay vì tự động xóa.

Các vấn đề cần chuyển sang M2.6¶

M2.6 cần kiểm tra quan hệ giữa target với Amount, Use Chip, MCC, các candidate feature thời gian và location.

Đối với categorical feature, fraud rate luôn phải được đọc cùng transaction_count và fraud_count để tránh kết luận mạnh từ category có support thấp.

Các temporal finding từ M2.3 cũng cần được giữ trong đầu khi diễn giải feature-target relationship, vì distribution của dataset không ổn định theo thời gian.

Các vấn đề cần chuyển sang M4¶

M4 cần quyết định representation / encoding phù hợp cho các categorical feature có cardinality khác nhau.

Không được mặc nhiên dùng cùng một chiến lược encoding cho Use Chip, MCC, Merchant State, Merchant City và Zip, vì cấu trúc cardinality của chúng rất khác nhau.

M4 cũng phải quyết định cách biến đổi Amount dựa trên bằng chứng M2.5 thay vì tự động xóa, clip hoặc lấy giá trị tuyệt đối.
